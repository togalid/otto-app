# oto — 音であそぼう

ローカルで動くブラウザ音楽ツール。親ディレクトリの自由研究／Tauriアプリとは独立しています。

公開・製品構成を検討する際は、[公開と収益化の検討方針](docs/RELEASE_STRATEGY.md)を参照してください。無料Web版と有料ローカル版の有力案、費用の構造、未決事項をまとめています。実装を確定する仕様ではありません。

## 起動

Node.js 22以降。インストール済み環境では再インストール不要です。

```sh
cd sound-playground
npm run dev
```

[http://localhost:4175](http://localhost:4175) を開きます。サーバーを終了すると接続できなくなります。LANにも公開するため信頼できるネットワークで使ってください。

通常の `npm run dev` はFull版です。別のターミナルで `npm run dev:free` を実行すると、[無料版プレビュー](http://127.0.0.1:4176/)を同時に開けます。

提供範囲は [dist/features.js](dist/features.js) で管理します。現在の切り替え対象はStem分離です。無料版でも原音の読み込み・再生を使えます。静的配信では `dist/edition.js` の無料設定が使われます。

ステム分離を使う場合は、Demucsをインストールした環境の実行ファイルを指定します。

```sh
OTO_DEMUCS=/path/to/venv/bin/demucs TORCH_HOME=/path/to/models npm run dev
```

`npm run dev` は `.env.local` の設定も読み込みます。上記2変数をこのファイルに保存すると、再起動後も設定を引き継げます（Git管理外）。

Stem分離のCPUスレッド数は既定で最大4です。必要なら `.env.local` の `OMP_NUM_THREADS`／`MKL_NUM_THREADS` で上書きできます。モデル・シフト・重なり率などの品質設定は変更しません。

ブラウザだけの静的配信でも演奏は使えます。ステム分離にはローカルNodeサーバーとDemucsが必要です。モデルは初回実行時にダウンロードされる場合があります。`/tmp` の環境・モデルは永続保存ではありません。

## できること

- スタイル、8小節のコード進行、キー、テンポ、ノリを選んで演奏。基本4パートと彩り4パートの音色・奏法・音量・ミュート・ソロを調整。
- コード画面のA〜Dに、それぞれ8小節の進行を設定できます。再生は選択中のセクションから始まり、8小節の終わりに「ループ」なら同じセクション、「次へ」なら次のセクションへ進みます。Dの次はAです。
- 8パッドまたは3オクターブ鍵盤で演奏。Ottoの演奏、ユーザーのフレーズへの応答。メロディはMono／レガート／長音ビブラート。
- MP3などを端末内で読み込むと、先に原音と波形を表示します。調整・再生を始めている間に、音源全体をローカルDemucsでVocal／Drum／Bass／Otherに分離します。BPM・メジャーキーの初期推定は手動操作前のみ反映し、作成済みの進行やパート設定は保持します。各StemのON／OFFと原曲パートの音量・ミュート・ソロを調整できます。再生中に分離が完了した場合は次の再生からStemを使います。分離を中断・失敗しても原音での調整と再生を続けられます。
- 設定保存／ロードからバージョン1 JSONで編成を持ち運び。原曲ファイルや生成済み演奏音声は保存に含みません。

テンポ・キーの推定には誤認識やテンポの半分／倍の解釈があり、読み込み後に手動で変更できます。短い音源や無音で推定できない場合は現在値を保ちます。短調の推定は平行長調のキーとして扱います。音声とStemはメモリ内だけに保持し、設定JSONには含めません。設定読み込みは再生を停止します。

## 構成と開発

`dist/` はソース兼公開ファイルです。ビルド不要のES modules + Web Audio + ローカルTone.js、JSDoc + TypeScript strictで開発しています。外部LLM、DB、認証、トラッキングは使っていません。

[変更箇所の案内・責務・コスト](docs/ARCHITECTURE.md)、[開発ルール](AGENTS.md)、[既存デザイン](docs/DESIGN_SYSTEM.md)。

```sh
# 編集中は影響するテストだけ
node --test tests/progression.test.mjs
# 統合時
npm run typecheck
npm test
```

親プロジェクトのTypeScriptを型チェックに利用します。通常の起動時やブラウザの更新時にテスト・型チェックは走りません。新しい開発環境のみ依存のセットアップが必要です。

HTTP配信はファイル更新を再検証します。Service Workerはありません。新しい公開モジュールはサーバーの許可リストにも追加してください。静的公開には `dist/` をまとめて配信し、JS/CSSも再検証する設定を使います。

## 原曲の位置合わせ

開始位置はA〜D共通です。セクション別の頭出しやコード進行の自動採譜は実行しません。音源全体の4つのStemを共有し、セクション切り替えで原曲を頭へ戻しません。原曲は共通の開始位置から音源末尾までをループします。明示的に小節から再生した場合は、その小節分の時間を共通の開始位置へ加えます。

開始位置スライダーは「全体」で大まかな頭出し、「微調整」で現在位置の前後0.5秒を調整できます。微調整の範囲は操作終了後に現在位置へ合わせ直します。←／→ボタン、またはスライダーの左右キーで0.01秒ずつ変更できます。ボタンの長押しで連続移動できます。波形は表示専用で、「全体」は8小節、「微調整」は2小節の範囲を表示します。

読み込み成功時はMP3のソロをONにして専用エリアを開きます。開始位置・微調整・波形はこのエリアにまとめ、MP3アイコンで再表示できます。「曲を外す」とMP3のソロも解除します。

波形の下の「最初の1拍を聴き比べる」は、共通の開始位置から1拍をループし、ルート音ノブの基準音を重ねます。ノブで音を合わせ、コードの度数（メジャースケールの1〜7）を指定するとキーを逆算できます。「キー … に合わせる」で全体キーへ反映します。例：F♯を4度にするとD♭。これは耳での確認を補助する機能で、自動判定ではありません。通常再生、位置・テンポ変更、音源削除、画面を離れた際には聴き比べを停止します。

耳でキーを合わせる際に度数を変更すると、その度数から始まるプリセットに切り替えます（現在のプリセットが同じ度数から始まる場合は保持）。キー反映時にはMP3とドラムのソロを解除し、原曲と伴奏を一緒に再生できる状態にします。

## 全曲コードと区間

コード画面は全曲共通で16小節ずつ表示します。A〜Dは連続した小節範囲に音色・奏法を割り当てる区間です。終了小節を変えると次区間の開始位置も動きます。区間のBPM・拍子は空欄／共通なら曲全体の設定を使います。曲末で停止します。従来の設定ファイルはA→B→C→Dのコードを順番につなぎ、各区間のパート設定を保持して読み込みます。新しい保存ファイルには全曲コードと区間範囲を保持します。コードアイコンはバッキング選択を表示します。区間は「分割して追加」で最大32区間まで増やせます。「区間を削除」はコードを保持して隣の区間へ統合し、前後移動ではコードを区間と一緒に移動します。コードのバッキングで「拍ごとに編集」を有効にすると、16分音符単位の発音ON/OFF・長さ・強さを区間ごとに保存できます。プリセットを選び直すと拍別編集を解除します。

## チュートリアル

ローカル開発中（localhost / 127.0.0.1）はチュートリアルNo.6の案内から開きます。公開ホストではメニューからNo.1へ進みます。吹き出しをタップ（キーボードではEnter）で進め、最後の案内から4拍のカウント後に演奏します。番号の選択後は吹き出しをタップして案内を開始します。「メロディ基礎」No.1〜5と「メロディ発展」No.6〜9を収録。No.6はド↔ソ、No.7は低いド↔高いドのスライドを交互に練習します。No.8〜9はファとシ以外の白い鍵盤から音を自由に選び、リズムだけを判定します。80 BPMでOttoの1小節と自分の1小節を4回交互に繰り返します。8小節で終了し、やり直し／次のレッスンへ進めます。成功したフレーズは4回分のリングに加算され、全部成功すると、はなまるになります。チュートリアル中はSpaceでOttoの案内を進めます。鍵盤はタッチ・マウス・フォーカスした鍵のEnterに対応します。

メニューへ戻る・番号変更・停止でチュートリアルの音を停止します。画面を離れてもレッスンは続き、押していた鍵盤の音は止まります。案内中に画面を離れても、メッセージの位置は保持します。フリー演奏の設定や保存データは変更しません。ドラム・ベース・バッキング編と進捗保存はまだありません。
